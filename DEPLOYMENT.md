# Vercel deployment

This project remains a static HTML/CSS/JavaScript POS, with Vercel Routing Middleware protecting the dashboard, stylesheet, scripts, and other private assets. The login API verifies an scrypt password hash on the server and issues a signed, HttpOnly session cookie.

## Configure admin credentials

1. Run `npm install` in the project folder.
2. To create a strong random password and save the hash and session secret locally, run `node scripts/generate-auth-secrets.js --generate-password --write-local`. The password is printed once for the admin to save; the `.env.local` file contains only the username, hash, and session secret and is ignored by Git. Alternatively, run `npm run auth:secrets` in an interactive terminal to enter your own password; it is masked while typing.
3. Configure these environment variables in the deployment environment:
   - `KCC_ADMIN_USERNAME` — defaults to `karthik` in the generator.
   - `KCC_ADMIN_PASSWORD_HASH` — generated by the command; never put the password itself in source code.
   - `KCC_SESSION_SECRET` — generated by the command.
4. Redeploy after setting or changing environment variables. Use HTTPS in production; Vercel sets secure session cookies for production deployments.

The login screen has a temporary browser-session cookie when “Keep me logged in” is unchecked. When checked, the signed cookie lasts 30 days. The temporary server session expires after 12 hours.

## Deploy

Import this folder as a Vercel project or run `vercel` from the project root. No frontend build command is required. Keep the project root as the deployment root so `vercel.json`, `proxy.js`, and `api/` are included.

`manifest.json` and the app icon are public so browsers can install the POS. All POS application pages, scripts, styles, and images require a valid session.

Bill history remains in browser LocalStorage, as in the original app. It is not shared or backed up between devices. The existing PhonePe UPI ID and QR generation remain unchanged.
